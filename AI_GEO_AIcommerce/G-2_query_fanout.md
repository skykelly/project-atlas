# G-2. Query fan-out·탐색·추천 경로

[목차](README.md) · [이전: 발견](G-1_ai_search_geo.md) · [다음: 콘텐츠 접근](G-3_crawlers_content_access.md)

> **핵심 결론**
> 복합 질문에 대응하려면 고객 과업과 제약을 근거로 분해하고, 각 근거가 최종 추천에 어떻게 기여하는지 검증해야 한다.

_공식 자료 확인일: 2026-10-06_

## 검증 근거에서 도출한 인사이트

### 1. 질문의 표현보다 해결 과업을 구조화한다

[Google 공식 설명](evidence/GOO-GEO-20261006-001.md)은 관련 하위 검색을 생성하는 fan-out을 확인해 준다. 이를 기업 지식 설계에 적용하면 ‘제품명 → 페이지’ 연결만으로 부족하고 고객의 목적·사용 환경·제약 → 필요한 근거의 대응표가 필요하다는 해석이다.

### 2. 하위 질의별 페이지 증식은 검증의 목표가 아니다

질문을 분해하는 것은 지식 누락을 찾기 위한 도구다. 동일한 문장을 조금씩 바꾸어 페이지를 늘리기보다 사양·설치·비교·사용 경험 근거를 연결하는 실험을 제안한다. 검색 시스템이 실제 생성한 질의를 관찰하지 못하면 내부 구현처럼 기록하지 않는다.

### 3. 의도·주제는 분석 단위가 되지만 모델 내부의 전부를 보여주지는 않는다

[Bing의 Intents·Topics](evidence/BING-MEASURE-20261006-001.md)는 인용과 연결된 맥락을 분석하는 공개 신호다. 레이블은 플랫폼의 분류이며 전체 고객 의도나 모든 하위 검색 목록으로 해석해서는 안 된다.

## 질문-근거 운영 모델 — 적용 가설

| 단계 | 기업이 정의할 것 | 검증 산출물 |
|---|---|---|
| 과업 | 고객이 끝내려는 일 | 질문 묶음 |
| 제약 | 공간·시간·예산·호환·관리 부담 | 필수·제외 조건 |
| 근거 | 사양·정책·시험·설치 정보 | 출처와 최신 버전 |
| 추천 | 후보가 조건을 만족하는 이유 | 근거 누락·오류 기록 |
| 피드백 | 재질문·이관·구매 실패 원인 | 지식 보강 목록 |

## 우선 실행안 — 적용 가설

‘밤에 사용하는 좁은 공간의 세탁기’ 같은 테스트 질문에서 설치 크기·사용 조건·소음 근거를 각각 확인한다. 동일 환경의 반복 답변을 비교하고 추천 이유·조건 누락을 기록한다. 순위나 fan-out 검색 횟수를 임의로 추정하지 않는다.

## 근거 범위

핵심 근거는 Google의 공식 구조 설명과 Bing의 관찰 지표다. 실제 플랫폼 화면·한국어 답변 재현 테스트는 아직 수행하지 않았다.

## 2026년 확장: 한 번의 답변에서 지속 과업으로

[Google Search agents·개인 맥락](evidence/GOO-SEARCH-20261006-001.md)과 [Amazon의 가격 추적·구매 이력 연결](evidence/AMZ-COMMERCE-20261006-001.md)은 탐색이 여러 회차·실행으로 이어지는 방향을 보여 준다. 이는 두 서비스의 비공개 fan-out 구조가 같다는 근거가 아니다.

| 고객 과업 예시 — 실험용 | 필요한 하위 근거 | 다음 실행에 필요한 확인 |
|---|---|---|
| 좁은 주방에 맞는 냉장고 비교 | 외형·문 열림·설치 여유·용량 | 현장 치수·배송 동선·설치 일정 |
| 기존 세탁기와 건조기 결합 | 모델별 호환·키트·보증 | 설치 옵션·기사 확인 |
| 예산 내 TV와 액세서리 구성 | 화면·입출력·거치·총액 | 부품 호환·프로모션·재고 |
| 원하는 가격까지 기다리기 | 현재 가격·조건·기간 | 알림 동의·최대 금액·최종 승인 |

질의 수가 늘어도 고객 효용이 좋아졌다고 단정하지 않는다. 답변 지연·반복 질문·조건 누락·작업 완료를 함께 본다. [UI/API audit](evidence/RES-AUDIT-20261006-001.md)을 참고해 실제 화면과 API 관측을 각각 기록하고 검색 수·내부 subquery를 보지 못한 경우 추정으로 남긴다.

권장 패턴은 질문→제약→근거→후속 실행의 대응표를 먼저 만들고, 반복 답변의 누락·충돌을 찾아 지식을 보완하는 것이다. ‘fan-out이 많으니 모든 조합 페이지를 만든다’는 접근은 [Google 고유 콘텐츠 기준](evidence/GOO-GEO-20261006-001.md)으로 재검토한다.

## 범위

고객의 복합 질문이 하위 질문·검색·조회·비교로 나뉘는 과정과 최종 추천까지의 연결을 조사한다. 이 문서에서 query fan-out은 조사 대상으로 사용하는 용어이며 모든 서비스가 같은 구조를 쓰거나 하위 질의를 공개한다고 가정하지 않는다.

## 핵심 연구 질문

- 복합 질문의 요구·제약·비교 기준을 어떤 단계로 분해하는가?
- 하위 검색은 브랜드·제품·사용 환경·가격·신뢰 신호 중 무엇을 확인하는가?
- 최신 정보, 서로 충돌하는 정보와 부족한 근거를 어떻게 처리하는가?
- 최종 답변에서 하위 근거와 추천 이유를 추적할 수 있는가?
- 원문에서 확인한 구조와 외부 관찰로 추정한 구조를 구분할 수 있는가?

## 비교·종합 기준

| 단계 | 확인할 사실 | 기업이 검증할 과제 |
|---|---|---|
| 의도 해석 | 질문·제약의 처리 방식 | 고객 언어와 제품 지식의 연결 |
| 하위 탐색 | 검색·도구·데이터 소스 | 필요한 근거의 누락 여부 |
| 후보 비교 | 필터·순위·비교 기준 | 제품의 적합성과 제외 조건 |
| 답변 구성 | 인용·불확실성·추천 이유 | 브랜드·제품 정보의 정확성 |

## LGE.com 적용 가설

고객 질문을 제품명보다 생활 과업·주거 조건·예산·관리 부담으로 분해하면 제품 지식의 누락을 더 잘 찾을 수 있다는 가설을 둔다. ‘설치 공간이 좁고 밤에 사용하는 세탁기’ 같은 질문에서 크기·설치 조건·소음 근거가 모두 제공되는지 확인한다. 이는 실험용 질문이며 실제 시스템의 동작 설명이 아니다.

## 측정과 한계

근거 누락률, 사실 오류율, 제약 충족률, 답변 재현성, 응답 시간과 필요한 경우 도구 호출 비용을 기록한다. 내부 검색이 보이지 않으면 최종 인용이나 화면만으로 검색 횟수·모델 구조를 단정하지 않는다.
