# G-2. AI 크롤러·콘텐츠 접근·llms.txt

[목차](README.md) · [발견·추천](G-1_ai_search_geo.md) · [측정](G-3_measurement.md) · [거래 실행](G-4_agentic_commerce.md)

_조사 범위: 2026-01-01~2026-10-06. 원문 확인일: 2026-10-06. 날짜 없는 운영 문서는 확인일의 상태로 기록한다._

> **핵심 판단:** AI가 제품 정보를 이용하는 경로는 검색 수집·학습·사용자 조회·상품 피드·도구·광고 검증으로 나뉜다. 기업은 목적별 접근 정책을 정하고, 읽을 수 있는 내용과 최신 판매 사실이 각 경로에서 일치하는지 검증해야 한다.

좋은 제품 설명이 있어도 차단 화면만 받거나 설치 조건이 이미지에만 남아 있으면 해당 경로에서 사실을 제대로 전달하기 어렵다. 반대로 페이지가 열려도 오래된 가격·해외 모델을 읽으면 잘못된 정보가 전달된다. **접근 가능, 내용 판독, 모델 식별, 최신 조건 전달**은 각각 다른 문제다. 이 문서는 이를 구분해 운영하는 기술·정보 전달 조건을 다룬다.

|---|---|---|---|
| OAI-SearchBot | ChatGPT 검색 발견 | 공개 제품·지원 정보 수집 | 허용이 노출 보장은 아님 |

[OpenAI 역할·공식 IP](evidence/OAI-CRAWL-20261006-001.md) · [Google·Anthropic·Perplexity 원문](evidence/PLAT-ACCESS-20261006-001.md)

사용자 조회라는 이름이 같아도 플랫폼의 정책이 동일하지 않다. 또한 user-agent 문자열은 위조될 수 있으므로 그것만으로 WAF(Web Application Firewall, 웹 방화벽)의 허용 근거를 확정하지 않는다. 지원하는 공식 IP·신원 검증 경로와 목적을 함께 대조하고, 로그에서 실제 요청·응답을 확인하는 설계가 필요하다.

**robots 정책과 보안의 구분**

- robots.txt는 준수하는 수집 주체에게 공개 crawl 의사를 전달한다. OpenAI는 검색 수집 차단 후에도 탐색용 링크가 표시될 수 있다고 설명하므로 차단과 완전한 검색 제거도 구분한다.
- 인증·권한 검사는 비공개 주문·개인 혜택·고객 정보의 접근을 통제한다.
- WAF·CDN 규칙은 요청의 통과·차단을 결정하며 robots 허용과 다르게 작동할 수 있다.
- 이 문서의 정책 비교는 실제 차단 우회나 사이트 설정 변경 결과가 아니다.

## 3. Google Search의 포함 통제와 학습·수집을 구분하기

| 통제 | 무엇을 다루는가 | 별도로 남는 것 |
|---|---|---|
| Googlebot crawl 정책 | 페이지 수집 | 색인·생성형 포함·노출 보장과 별개 |
| Search Console 생성형 AI control | AIO·AI Mode·Discover의 적용 기능에 사이트 링크·내용 포함/제외 | 일반 Search 순위·포함, Merchant Center·Ads 참여는 별도 |
| Google-Extended | 문서에 명시한 학습·Gemini/Vertex grounding 이용 | Search 포함·순위 통제가 아님 |
| noindex | 검색 색인 제외 | 실제로 읽을 수 있어야 지시가 처리됨 |
| 인증·권한 | 비공개 자원 접근 | 공개 검색의 노출 관리와 다른 책임 |

[통제 원문과 범위](evidence/PLAT-ACCESS-20261006-001.md)

Search Console의 control은 부모 속성 설정을 상속하거나 자식 속성에서 별도로 지정할 수 있다. 따라서 제품 영역의 설정을 보지 않고 최상위 도메인 설정만으로 전체 상태를 판단하면 안 된다. 기본 포함 상태와 실제 적용 상태도 구분한다. 이 control은 학습 통제를 대신하지 않으며, Google-Extended를 바꾼 것만으로 Search 생성형 노출이 차단됐다고 판단할 수 없다.

정책 선택에는 명시한 목적과 영향 범위를 남긴다. 예를 들어 공개 사양은 발견에 제공하면서 비공개 주문 상태는 인증된 도구로만 전달하는 설계가 가능하다. 그러나 공개되어서는 안 되는 정보를 먼저 올린 뒤 robots로 보호하는 방식은 적절한 접근 통제가 아니다.

## 4. llms.txt·Markdown·구조화 데이터의 실제 역할

| 수단 | 활용할 수 있는 목적 | 이번 근거가 지지하지 않는 주장 |
|---|---|---|
| llms.txt | 이를 이용하는 서비스에 자료 안내 | 설치하면 Google AI 추천·순위 향상 |
| Markdown | 위키의 지식 원본·검토·버전 관리 | 웹을 Markdown으로 바꿔야 Google에 등장 |
| 구조화 데이터 | 지원 검색 기능의 정보 표현 | 특별 GEO schema가 자연 답변을 보장 |
| 제목·표·목록·문단 | 사람과 도구가 사실·조건을 이해하도록 표현 | 일정한 길이·잘게 나누기가 모든 AI에 필수 |
| 접근성 label·role·state | 브라우저 agent의 화면·조작 이해 지원 | 접근성 개선만으로 거래 승인·노출 보장 |

[Google 범위의 공식 명확화](evidence/GOO-LLMS-20261006-001.md) · [가이드](evidence/GOO-GEO-20261006-001.md) · [ChatGPT Atlas 접근성 FAQ](evidence/OAI-REFERRAL-20261006-001.md)

Atlas 위키에서 Markdown을 기준으로 쓰는 이유는 사실·근거·변경을 검토하고 재사용하기 위해서다. 이를 외부 AI 검색이 요구하는 특별 파일 형식으로 혼동하지 않는다. 사이트에서도 표와 설명 문단은 고객의 이해를 돕도록 사용하고, 특정 AI가 읽지 못하는 항목은 실제 전달 경로에서 확인한다. 다른 서비스가 llms.txt를 지원한다면 지원 목적·호출·갱신 책임을 확인해 별도로 활용할 수 있다.

| Adobe 도구 점수 | 관측·발표 조건 | 판독 |
|---|---|---|
| 제품 페이지 66% | 미국 retail, 2026-04 발표 | 상품 상세의 판독 격차 |

[Adobe 측정 조건](evidence/ADI-MARKET-20261006-001.md)

이 값은 Adobe 기계 가독성 도구의 점수이며 플랫폼의 인용률·순위·추천 정확도·CVR가 아니다. 제품 페이지에서 어떤 필수 사실이 전달되지 않는지 찾는 데 참고할 수 있지만, 공급사 점수를 높였다는 이유로 구매 효과를 확정할 수는 없다.

| 점검 대상 | 가전 예시 | 비교·기록할 것 |
|---|---|---|
| 응답 | 지역·봇별 403/429, CAPTCHA, 로그인 요구 | 목적·국가·시간·코드·차단 원인 |
| 원문 내용 | 설치 여유·호환 도표가 이미지에만 존재 | 필수 사실과 텍스트 설명의 대응 |
| 렌더링·상호작용 | 펼친 뒤 나타나는 보증·반품 예외 | raw 응답·실제 DOM·사용자 화면 차이 |
| 모델·지역 | 해외 모델·통화·기본 옵션으로 이동 | URL·canonical·국내 모델·변형 |
| 갱신 | 웹·피드의 가격·재고·정책 충돌 | 원천 버전·변경/반영 시각 |
| 조작 가능성 | 옵션·예약 버튼의 label·상태 불명확 | 이름·역할·선택 상태·실패 메시지 |

모든 AI가 JavaScript를 읽지 못한다고 가정하지 않는다. Google은 차단되지 않은 JS 처리와 기존 JS SEO 원칙을 안내하며, 브라우저 agent의 관찰 방식도 원문 crawl과 다르다. 문제를 ‘AI가 못 읽음’으로 한데 묶지 말고 어느 경로에서 어떤 내용이 빠지는지 기록해야 개선할 수 있다.

## 6. 웹·피드·앱·거래의 전달 경로를 분리하기

| 경로 | 전달할 정보·기능 | 준비 조건 | 성공 판정 — 제안 |
|---|---|---|---|
| 공개 웹 | 제품·시험·설치·정책 | 접근·색인·본문·URL | 올바른 사실·국내 모델을 읽음 |
| 상품 피드 | 상품·변형·가격·재고·이미지 | 승인·지원 명세·시장·갱신 | 처리 상태와 웹/피드 정합성 |
| 연결 앱·도구 | 설치·혜택·주문 등 필요한 조회 | 심사·사용자 동의·권한 | 필요한 범위의 조회·실패 이관 |
| 거래 API | 견적·승인·주문·상태 | 판매자·결제 승인·운영 계약 | 승인 조건과 단일 유효 주문 |
| 광고 landing | 광고 제출 페이지의 근거·적합성 | 해당 검증 경로의 접근 | 소재와 실제 구매 조건 일치 |

[피드](evidence/OAI-FEED-20261006-001.md) · [앱](evidence/OAI-PLUGINS-20261006-001.md) · [거래 책임](evidence/OAI-CHECKOUT-20261006-001.md)

피드의 국가·통화·checkout 필드는 실제 시장 활성화나 승인 완료의 증거가 아니다. 정적 사양을 전달하는 일과 고객 주소의 설치 슬롯·개인 혜택을 확정하는 일도 다르다. 앞의 정보는 공개 원문·상품 피드에, 뒤의 정보는 권한 있는 조회·상담에 배치하는 설계가 필요하다. 모든 필요한 항목이 플랫폼의 기본 schema에 존재한다고 가정하지 않는다.

## 7. 갱신과 정합성 운영 — 가전 설계 예시

| 변경 | 원천 담당이 확정할 것 | 함께 점검할 경로 | 실패 시 고객 영향 |
|---|---|---|---|
| 국내 모델·옵션 추가 | 식별자·호환·제약 | 웹·피드·상담·구매 URL | 다른 모델 추천·옵션 손실 |
| 가격·혜택 변경 | 기간·중첩·대상·총액 | 소재·피드·landing·견적 | 적용 불가 혜택 약속 |
| 재고·서비스 지역 변경 | 지역 구매·이행 가능 여부 | 추천 데이터·조회·checkout | 구매 또는 설치 실패 |
| 설치·반품 정책 변경 | 유효일·예외·책임 | 가이드·FAQ·상담·동의 | 조건 오해·불필요한 지원 |

외부 AI가 기존 내용을 언제 다시 수집하는지는 기업이 완전히 통제하지 못한다. 원천에서 바꾼 시점, 자사 전달 경로에 반영된 시점, 외부 답변에서 관측한 시점을 나누어 기록한다. 캐시·crawl 주기·피드 처리와 사실 오류를 구분해야 잘못된 담당자나 시스템에 개선을 요구하지 않는다.

**운영 기록의 최소 항목**

- 국가·모델·옵션·URL과 근거 원천·책임자.
- 정보 버전·확정 시각·전달 시각·외부 확인 시각.
- 봇/도구 목적·검증된 신원·응답·필수 사실 누락.
- 오류 유형·영향 경로·수정·재확인 결과.

## 8. 검증 순서와 지표

| 순서 | 점검 | 남길 결과 |
|---|---|---|
| 1. 목적·범위 | 공개/비공개, 검색/학습/조회/광고, 속성 상속 | 목적별 허용·차단 결정과 근거 |
| 2. URL 표본 | 대표 제품·설치·정책·옵션 선정 | 국가·페이지 종류·책임자 |
| 3. 접근·판독 | 응답·raw·렌더링·도구별 대조 | 차단과 사실 누락 분리 |
| 4. 정합성 | 같은 모델의 웹·피드·견적 비교 | 충돌·갱신 지연·수정 |
| 5. 결과 | 동일 조건 재확인·실제 답변 관찰 | 접근 개선과 추천 성과 별도 |

| 지표 — 운영 제안 | 분모·정의 | 필요한 기록 |
|---|---|---|
| 접근 성공률 | 성공 응답 / 목적이 같은 시도 | 봇·국가·상태 코드·시간 |
| 필수 정보 가독률 | 읽힌 필수 항목 / 지정 항목 | 항목·경로·추출 방식 |
| 웹/피드 일치율 | 일치 모델-필드 / 비교 모델-필드 | 원천·버전·시점 |
| 갱신 지연 | 원천 변경부터 대상 경로 반영까지 | 두 시각·허용 지연 |
| 오래된 사실 비율 | outdated 사실 / 평가 사실 | 질문·모델·올바른 값 |

같은 접근 성공률이라도 봇 목적·페이지 표본이 달라지면 직접 비교하기 어렵다. 계정·보안 설정을 바꾸기 전에 평가 범위를 고정하고, 추천·방문·구매의 효과는 [G-3](G-3_measurement.md)에서 별도로 확인한다.

_검증 범위: 공식 문서의 목적·통제·제공 조건을 확인했다. LGE.com의 robots·CDN·WAF·원문·로그·계정 설정을 실제 검사하거나 변경하지 않았다. 표의 사이트 점검·갱신·지표는 운영 설계다._
