# G-5. Agentic Commerce·Zero-click Shopping

[목차](README.md) · [이전: 성과 측정](G-4_measurement.md) · [변경 이력](LOG.md)

> **핵심 결론**
> Agentic Commerce는 발견용 상품 정보, 거래 실행, 사용자 승인·판매자 책임의 연결이다. 기술 문서와 해외 출시만으로 한국 상용화나 매출 효과를 판단해서는 안 된다.

_공식 자료 확인일: 2026-10-06_

## 검증 근거에서 도출한 인사이트

### 1. 피드 제출·검색 노출·결제는 각각의 자격과 구현을 갖는다

[OpenAI 상품 피드](evidence/OAI-FEED-20261006-001.md)와 [ACP checkout](evidence/OAI-CHECKOUT-20261006-001.md)은 발견과 거래의 경계를 보여 준다. 기업의 준비는 데이터 정합성 검토와 거래·국가 자격 확인을 따로 진행해야 한다는 해석이다.

### 2. 외부 AI 화면에서도 판매자의 실행 책임은 남는다

에이전트가 고객을 대신해 거래를 준비하더라도 설치·배송·환불·중복·승인 실패를 처리할 기업 시스템이 필요하다. 가전에서는 추천 정확도 외에 ‘이 조건으로 실제 주문 가능한가’를 검증하는 흐름을 설계하는 것이 중요하다는 적용 가설이다.

### 3. 브랜드 상담과 거래 경로가 검색·광고 화면으로 확장된다

[Google의 9월 업데이트](evidence/GOO-COMMERCE-20261006-001.md)는 기능별 국가·beta·점진 제공을 나눈다. 홈페이지를 방문하지 않고 질문을 해결하는 흐름과 외부에서 거래까지 완료하는 흐름은 각각 고객 관계·측정 과제가 다르다.

### 4. 속성 반영률은 구매 성과가 아니다

추천에 상품 속성이 반영된 비율은 정보 활용 신호다. 전환·매출·증분 마진은 추가 근거가 필요하다. 플랫폼이 제시한 평균이나 단일 브랜드 테스트를 국내 가전의 기대 효과로 적용하지 않는다.

## 비교 종합

| 경로 | 확인한 단계 | 한국 적용 판단 |
|---|---|---|
| OpenAI 발견용 피드 | 승인·Stable·시장 설정 | 한국 판매 지원 미확인 |
| OpenAI ACP checkout | 판매자 시스템의 주문·결제 | 파트너·시장·거래 조건 별도 확인 |
| Google UCP hub 업데이트 | 미국 점진 제공, 일부 후속 일정 | 신규 기능의 한국 제공 미확인 |
| Google 외부 브랜드 상담 | Search와 미국 YouTube beta | 제품별 국가·자격 구분 |

## 우선 실행안 — 적용 가설

1. 소량 SKU로 식별자·변형·가격·재고·설치·배송·반품 정의를 점검한다.
2. 발견과 거래 데이터를 연결하되 국가·판매자 자격을 먼저 확인한다.
3. 주문 전 승인·중복 방지·취소·고객 이관의 조건을 문서화한다.
4. 외부에서 질문만 끝난 경우와 거래까지 끝난 경우의 고객 관계·측정 방안을 분리한다.

한국 서비스에 새 결제 연동을 적용하거나 실제 주문 테스트를 수행한 것은 아니다.

## 2026년 chronology로 교정한 거래 방향

[OpenAI의 03-24 발표](evidence/OAI-DISCOVERY-20261006-001.md)는 초기 Instant Checkout의 유연성 한계를 인정하고 상품 발견·판매자 자체 checkout으로 중심을 옮겼다. 따라서 기존 기술 문서의 승인 파트너 구현 설명을 전체 ChatGPT 판매자의 표준 거래 경로로 해석하지 않는다. [Plugins 문서](evidence/OAI-PLUGINS-20261006-001.md)도 일반 외부 checkout과 선정 marketplace embedded beta를 나눈다.

| 경로·근거 | 발견→거래 연결 | 남는 제약·책임 |
|---|---|---|
| OpenAI ACP·판매자 checkout | 피드·비교·인앱 브라우저·브랜드 앱 | 발견/앱/결제 승인 분리, 판매자 이행 |
| [Google UCP·Cart](evidence/GOO-UCP-20261006-001.md) | 여러 판매자 cart·Google 결제 또는 cart transfer | 발표·미국 제공·후속 국가 구분 |
| [Microsoft Copilot](evidence/MS-COMMERCE-20261006-001.md) | catalog·checkout·계정/로열티 | 미국 초기 제공·판매자 관계 유지 |
| [Perplexity Instant Buy](evidence/PER-COMMERCE-20261006-001.md) | 적격 상품 카드·저장 정보·판매자 주문 | 미국·적격 판매자·지원 이관 |
| [Amazon Alexa shopping](evidence/AMZ-COMMERCE-20261006-001.md) | 구매 이력·조건부 구매·반복 주문 | 미국 기능·권한·merchant별 이행 |

### 프로토콜 역할

| 이름 | 역할·확인 범위 | 혼동하지 않을 것 |
|---|---|---|
| ACP | OpenAI·Stripe 출발, 2026 발견까지 확장 | Google UCP와 이름·시장 자격이 다름 |
| UCP | Google·Shopify 축 commerce 상호운용 | 공개 표준과 특정 플랫폼 상용 지원은 별개 |
| MCP | 에이전트와 지원 도구 연결 | 자체 구매·결제 자격을 부여하지 않음 |
| AP2 | 결제 권한·조건·기록의 검증 | UCP 전체 catalog·checkout을 대체하지 않음 |

**권장 실행 순서:** 정확한 catalog→최신 가격/재고→설치/배송 조건→고객 승인→주문/사후관리. 내장 결제 확대보다 국가·자격·사용자 경험이 먼저다. zero-click 답변, 외부 발견 뒤 자사 checkout, 플랫폼 안 구매 완료를 각각 측정한다.

## 범위

AI가 탐색·비교·추천·장바구니·주문·결제·사후관리를 돕거나 실행하는 거래 흐름의 변화를 조사한다. 서비스가 에이전트라고 부르는지보다 실제로 수행하는 단계와 권한을 확인한다.

Zero-click은 자사 사이트 방문 없이 답변·추천이 완료되는 경우와 외부 화면에서 거래까지 완료되는 경우를 구분한다. 두 흐름을 하나의 지표로 묶지 않는다.

## 핵심 연구 질문

- AI는 정보를 추천하는가, 거래를 준비하는가, 실제 구매까지 실행하는가?
- 사용자 동의·권한·승인·금액 한도·취소·복구는 어떻게 설계되는가?
- 가격·재고·배송·반품·보증 정보를 어떤 주체가 책임지는가?
- 판매자 참여 자격, 국가·언어, 제품군과 결제 수단의 제한은 무엇인가?
- 거래 수수료·광고·추천 순위·고객 데이터 접근은 어떻게 달라지는가?

## 실행 단계별 비교

| 단계 | 확인할 실제 기능 | 주요 조건·보호 지표 |
|---|---|---|
| 탐색·추천 | 후보 검색·비교·적합성 설명 | 사실 오류·편향·후보 누락 |
| 거래 준비 | 재고·가격 조회·장바구니 | 정보 신선도·옵션·설치 조건 |
| 주문·결제 | 사용자 승인·거래 생성 | 권한·인증·중복 주문·금액 한도 |
| 사후관리 | 배송 조회·취소·반품 | 책임·복구·정책·고객 이관 |

## LGE.com 적용 가설

가전 거래에서는 제품 추천 이후 설치·배송·기존 제품 처리·보증 등의 조건 확인이 중요하다는 가설을 둔다. 에이전트 친화적인 상품 정보와 거래 인터페이스를 검토하되, 원문 검증 전 특정 프로토콜·플랫폼 지원을 도입 결정으로 연결하지 않는다.

Brand Answer Engine은 외부 추천의 근거를, AI Chat은 자사 상담·조건 확인과 실행 경로를 담당하는 연결을 검토한다. 외부 플랫폼에서 구매가 끝나는 경우 고객 관계와 사후관리 접점에 어떤 변화가 생기는지 별도로 평가한다.

## 측정과 한계

추천 채택률, 거래 준비·승인·완료율, 실패·중복·취소율, 설치 조건 오류, 고객 이관과 마진을 함께 본다. 외부 플랫폼에서 자사 사이트 클릭이 줄어도 전체 수요 감소로 단정하지 않으며, 매출 증가도 에이전트의 증분 기여로 바로 해석하지 않는다.
