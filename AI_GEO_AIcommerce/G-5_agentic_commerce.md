# G-5. Agentic Commerce·Zero-click Shopping

[목차](README.md) · [발견·탐색](G-1_ai_search_geo.md) · [광고](G-6_ai_ads_monetization.md)

> **핵심 결론:** 2026년 AI commerce는 상품 발견, 판매자 checkout, 플랫폼 내 거래, 조건부 구매가 함께 존재한다. 가전은 설치·배송·옵션·서비스까지 검증해야 하므로, 내장 결제를 먼저 붙이기보다 실제 주문 가능한 조건과 판매자 책임을 설계해야 한다.

_조사 창: 2026-01-01~2026-10-06. 근거 확인일: 2026-10-06._
이 문서는 **상품 정보→주문→결제→사후관리의 실행 조건**을 다룬다. 플랫폼 전체 전략은 [G-7](G-7_platform_ecosystems.md), 광고 제안과 비용은 [G-6](G-6_ai_ads_monetization.md), 성과 정의는 [G-4](G-4_measurement.md)에서 관리한다.

## 2026년 거래 모델의 변화

| 시점·플랫폼 | 구체적인 연결 | 공식 단계·조건 | 판매자에게 남는 일 |
|---|---|---|---|
| 01-08 [Microsoft](evidence/MS-COMMERCE-20261006-001.md) | Copilot.com checkout, PayPal·Shopify·Stripe | 미국 점진 제공, 참여 경로별 자격 | 거래·고객 관계·이행 |
| 01-11·05-19 [Google](evidence/GOO-UCP-20261006-001.md) | UCP·여러 판매자 Universal Cart·Google 결제/cart transfer | 미국 초기·여름 예고, 다른 접점은 후속 | 옵션·배송·멤버십·seller of record |
| 03-24 [OpenAI](evidence/OAI-DISCOVERY-20261006-001.md) | ACP 발견 확대·판매자 자체 checkout·Walmart 브랜드 앱 | 초기 Instant Checkout 유연성 한계 인정 | 브랜드 UX·자사 결제·이행 |
| 06-11 [Amazon 후속](evidence/AMZ-COMMERCE-20261006-001.md) | 구매 맥락·가격 추적·조건부 구매·반복 주문 | 미국 통합 쇼핑 기능 설명 | 상품·재고·구매 권한·지원 |
| 09-16 [Google 후속](evidence/GOO-COMMERCE-20261006-001.md) | UCP hub cart transfer·checkout 테스트 | 미국 점진, 호주·캐나다 2027년 초 예고 | 연결 검증·실행 조건·예외 처리 |
| 현행 [Perplexity](evidence/PER-COMMERCE-20261006-001.md) | Instant Buy의 저장 정보·직접 판매자 주문 | 미국 적격 상품, Enterprise Pro/Max 제외 | 배송·상품·이행 문의 |
| 현행 [ChatGPT Plugins](evidence/OAI-PLUGINS-20261006-001.md) | 외부 checkout 권장·embedded payment sheet | physical goods, 선정 marketplace beta | 결제·세금·배송·환불 |

‘coming months’가 지났다는 이유로 실제 제공 완료로 바꾸지 않는다. OpenAI의 2025년 Etsy Instant Checkout 발표는 배경이며, 2026년 일반 판매자의 기본 경로로 그대로 유지하지 않는다. 국가·판매자·SKU 자격은 실제 참여 판단의 선행 조건이다.

## Zero-click을 세 경로로 분리한다

| 경로 | 자사 방문·거래 | 고객 관계·측정 과제 |
|---|---|---|
| 답변만 완료 | 자사 방문 없이 질문 해결, 구매 없음/미관측 | 정확한 근거·사후 직접 방문을 단정하지 않음 |
| 외부 발견→자사 checkout | AI에서 선별한 뒤 자사 브라우저/페이지에서 구매 | 옵션·조건 유지, referral·주문 연결 |
| 플랫폼 내 거래 | 자사 웹 세션 없이 주문/결제 연결 가능 | 주문 로그·고객 동의·지원 책임·거래 귀속 |

사이트 방문 감소가 전체 수요 감소를 뜻하지 않지만, 외부 답변이 있었다고 모두 구매 기여로 세지도 않는다. 웹 분석 외에 판매자 주문 데이터와 거래 경로 기록이 필요하다는 설계 제안이다.

## 프로토콜과 참여 자격의 경계

| 요소 | 확인된 역할·근거 | 구현 전에 확인할 조건 |
|---|---|---|
| ACP | OpenAI·Stripe 출발, 2026 발견까지 확대 | 피드·시장·파트너·checkout 승인 |
| UCP | Google·Shopify 축 거래 상호운용, 다른 ecosystem 연결 | 대상 플랫폼·지원 시장·실제 integration |
| MCP | 지원 도구 연결 | 도구 권한·사용자 연결·지원 작업 |
| AP2 | 결제 조건·권한·기록의 검증 | 실제 제품 지원·한도·승인·위임 |
| 상품 피드 | catalog·가격·재고·발견 데이터 | schema·신선도·변형·국가 |
| 판매자 checkout | 주문 조건·결제·이행 | merchant 책임·복구·지원 |

세부 역할은 [UCP 근거](evidence/GOO-UCP-20261006-001.md), [ACP checkout](evidence/OAI-CHECKOUT-20261006-001.md), [Plugins](evidence/OAI-PLUGINS-20261006-001.md)로 연결한다. 표준이 공개됐다는 사실은 우리 판매자가 모든 AI 플랫폼에서 거래할 자격을 얻었다는 뜻이 아니다.

## 피드 준비와 거래 준비를 따로 진행한다

[OpenAI 현행 피드](evidence/OAI-FEED-20261006-001.md)는 승인 파트너, Stable 지원 경로, 기본 미국 시장과 추가 시장 설정을 구분한다. Draft는 운영 지원 명세로 간주하지 않는다. 국가/통화 필드와 checkout 플래그만으로 한국 판매·KRW 결제·내장결제 온보딩이 완료되지 않는다.

아래는 **가전용 공통 데이터 준비표**이며 모든 항목이 각 플랫폼의 기본 schema에 존재한다는 주장이 아니다. 기본 필드·확장 속성·별도 조회 도구 중 전달 위치를 실제 명세에 맞춰 결정한다.

| 데이터 묶음 | 필요한 사실 | 갱신·확인 시점 |
|---|---|---|
| 제품/변형 | 국가 모델·옵션·식별자·호환 액세서리 | catalog 등록·변경 |
| 가격/혜택 | 판매가·조건·멤버십·중첩·만료·총액 | 추천 snapshot과 최종 주문 시점 |
| 재고/지역 | 구매 가능한 수량·서비스 지역 | 고객 위치 확인·결제 직전 |
| 설치/배송 | 크기·동선·필수 공사·일정·수거 | 고객 조건 확인·슬롯 예약 |
| 정책 | 보증·설치 후 반품·취소·문의 경로 | 약관 버전·최종 동의 |
| 주문/지원 | 주문 ID·상태·변경·환불·지원 주체 | 이벤트·실패/재시도 |

## 냉장고 구매를 끝내기 위한 실행 흐름 — 가상 설계

**고객 요청:** “지금 냉장고를 교체하고 싶은데, 주방에 맞고 이번 주 설치가 되는 제품을 찾아줘.”

| 단계 | 에이전트가 확인할 것 | 판매자 시스템/담당자가 확정할 것 | 다음 단계 진행 조건 |
|---|---|---|---|
| 탐색 | 용량·예산·사용 과업·후보 | 국내 모델·사양·제외 조건 | 필요한 고객 조건 확보 |
| 설치 판단 | 치수·문 열림·배송 동선·전원 | 설치 가능성·추가 작업·현장 확인 필요 | 불확실한 설치 조건 해소 또는 이관 |
| 거래 준비 | 옵션·설치일·수거·멤버십 | 재고·일정·혜택·세금/비용·총액 | 실행 가능한 유효 견적 |
| 사용자 승인 | 제품·옵션·일정·총액·정책 확인 | 동의 기록·결제 권한·한도 | 승인한 조건과 견적 일치 |
| 주문/결제 | 승인한 주문 제출 | 중복 방지·결제/주문 상태·이행 | 단일 유효 주문·확인 정보 |
| 사후관리 | 설치 안내·상태·변경 요청 | 변경/취소·환불·기사/상담 이관 | 고객과 판매자가 같은 상태를 확인 |

AI가 제품을 잘 골라도 설치일이 확보되지 않거나 총액이 바뀌면 같은 조건으로 구매를 완료할 수 없다. 설치 가능성 확인을 결제 뒤로 미루는 흐름은 별도 위험 항목으로 관리한다.

## 승인·실패·복구를 설계하는 기준

[ACP 기술 설명](evidence/OAI-CHECKOUT-20261006-001.md)은 주문 검증·배송·세금·위험·승인·결제를 판매자 시스템 책임으로 나누고 위임 금액·만료 조건을 둔다. 다음은 가전 pilot의 운영 설계 제안이다.

| 상황 | 처리 원칙 | 남길 상태·로그 |
|---|---|---|
| 견적 후 가격/재고 변경 | 새 조건을 알려 재승인 또는 후보 변경 | 이전/새 견적·만료·승인 |
| 응답 지연·재시도 | 동일 요청의 중복 주문 여부 확인 | 요청/주문 ID·최종 상태 |
| 결제 성공·주문 상태 불명 | 성공을 재결제 요청으로 처리하지 않고 조회·지원 이관 | 결제/주문 상태·불일치 |
| 설치 일정 불가 | 대체 일정/제품을 제시하고 고객 선택 | 예약 상태·변경 동의 |
| 사용자 조건 초과 | 금액·브랜드·시간 등 승인 범위 밖 실행 중단 | 위반 조건·추가 승인 |
| 취소·환불·지원 | 판매자 책임과 플랫폼 이관 경로를 명시 | 담당 주체·처리 상태·고객 안내 |

## 단계별 KPI와 확대 판단 — 제안

발견 후보의 정확도, 유효 견적 비율, 승인→주문 완료율, 중복/실패/취소율, 설치 약속 이행, 환불·지원 이관·마진을 함께 본다. 분모는 요청·견적·승인·주문으로 구분하고 실패 원인을 제품·고객 조건·플랫폼·판매자 시스템으로 기록한다.

우선순위는 국가/판매자 자격 확인 → 대표 SKU 데이터 정합성 → 주문 없는 견적·이관 테스트 → 승인된 환경의 거래 pilot이다. [Google의 50% 속성 반영·+5% 평균 전환 주장](evidence/GOO-COMMERCE-20261006-001.md)은 각각 추천 활용·공급사 관찰이지 가전 pilot 목표가 아니다. 내장 결제의 범용 수수료·한국 지원·매출 효과는 미확인이다.

[기존 전환 종합](../AI_SalesMarketing/1-2_conversion.md)과 [신규 수익모델](../AI_SalesMarketing/1-5_new_revenue_models.md)은 별도 사례 원문으로 연결한다. 실제 판매자 신청·피드 제출·결제 연동·주문·설치 테스트는 수행하지 않았다.
