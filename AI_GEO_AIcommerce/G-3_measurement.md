# G-3. AI 유입·성과 측정·벤치마크

[목차](README.md) · [발견·추천](G-1_ai_search_geo.md) · [콘텐츠 접근](G-2_crawlers_content_access.md) · [거래](G-4_agentic_commerce.md) · [광고](G-5_ai_ads_monetization.md)

_조사 범위: 2026-01-01~2026-10-06. 원문 확인일: 2026-10-06. 내부 AI referer MAU 실측값은 공개하지 않는다._

> **핵심 판단:** AI 성과는 고객 질문의 해결 품질, 플랫폼 노출·인용, 식별 방문, 주문·고객 가치로 나누어 연결해야 한다. 각 도구의 분모·기간·관측 범위를 고정하고, 귀속 성과와 실제 추가 효과를 구분해야 사업 판단에 사용할 수 있다.

AI 답변에 제품이 나와도 고객이 클릭하지 않을 수 있고, 자사 사이트를 방문하지 않아도 승인된 거래 연결로 주문이 생길 수 있다. 따라서 AI의 영향을 웹 유입만으로 모두 읽기는 어렵다. 반대로 브랜드 언급이 늘었다는 이유로 주문 기여가 늘었다고 확정할 수도 없다. 이 문서는 **무엇을 관측했는지와 무엇을 아직 알 수 없는지**를 같은 보고서에서 드러내는 측정 기준을 다룬다.

## 1. 연결하되 합산하지 않는 네 가지 관측

| 관측 | 확인하는 질문 | 자료 | 알 수 없는 범위 |
|---|---|---|---|
| 질문·답변 품질 | 요구에 맞는 제품과 조건을 설명했는가? | 실제 UI 평가·근거 판정 | 모든 고객의 실제 노출·매출 |
| 플랫폼 노출·인용 | 어느 접점·의도에서 출처가 보였는가? | Search Console·Bing·판매자 도구 | 전체 AI 인구·모든 방문 |
| 식별 방문 | AI에서 자사로 얼마나 이동했는가? | referrer·UTM·웹/앱 분석 | 클릭 없는 영향·미식별 복귀 |
| 사업 결과 | 주문·설치·신규 고객·마진으로 이어졌는가? | 주문·CRM·서비스·광고 실험 | 인과 효과는 별도 설계 필요 |

한 고객의 여러 질문, 같은 답변의 복수 인용, 반복 방문과 최종 주문은 다른 단위다. 노출→방문→주문을 연결해 읽을 수는 있지만 서로 다른 모집단을 같은 funnel의 정확한 전환율처럼 계산하면 안 된다. 개별 연결이 불가능한 부분은 미관측 범위로 남겨야 한다.

[Google 보고서](evidence/GOO-MEASURE-20261006-001.md) · [Bing](evidence/BING-MEASURE-20261006-001.md) · [Merchant Center](evidence/GOO-COMMERCE-20261006-001.md) · [ChatGPT UTM](evidence/OAI-REFERRAL-20261006-001.md) · [광고 측정](evidence/OAI-ADS-20261006-001.md)

측정 수단은 확대됐지만 각각 자신의 접점을 관찰한다. Search Console의 과거 Web 전체 포함 설명과 최신 별도 생성형 보고서는 날짜를 구분해 읽어야 한다. 최신 보고서가 있다고 한 도구로 모든 AI의 고객 행동을 볼 수 있는 것은 아니다.

### Google 보고서를 읽을 때

- **시간대:** PT 날짜와 한국 시간 집계를 맞춘 뒤 기간을 비교한다.
- **집계:** 속성 단위와 페이지 단위가 다르다. 같은 사이트의 링크 두 개가 한 화면에 있으면 속성 합계와 페이지 합계가 다를 수 있다.
- **URL:** canonical·리디렉션 기준과 실제 landing의 차이를 확인한다.
- **자료 상태:** 최신 잠정값·표시되지 않는 자료·내보내기 처리 규칙을 보존한다.

[집계·내보내기 조건](evidence/GOO-MEASURE-20261006-001.md). 화면에 보고서가 없다는 이유만으로 노출이 0이라고 확정하지 않는다. 노출 부족·접근·단계적 제공 잔존 안내와 포함 설정을 확인해야 한다.

### Bing Citation Share를 읽을 때

Citation Share는 같은 grounding query에서 전체 인용 중 자사 인용의 비율이다. 예를 들어 한 질의의 인용 100개 중 자사 20개라면 20%라는 해석용 계산이 가능하다. 그러나 다른 질의의 인용 수·비중이 바뀌면 전체 평균도 바뀔 수 있으며, 이를 한국 시장 점유율이나 구매 기여로 바꿀 수는 없다. Intents·Topics는 어떤 의도·주제에서 근거가 쓰이는지 관찰하는 보조 차원이다. [공식 정의](evidence/BING-MEASURE-20261006-001.md)

## 3. 기업 보고서의 지표 사전 — 설계 제안

| 지표 | 분모·계산 | 반드시 고정할 조건 |
|---|---|---|
| 브랜드 언급률 | 언급 답변 / 유효 평가 답변 | 질문·플랫폼·국가·언어·반복 수 |
| 정확한 제품 추천률 | 적합 모델 추천 답변 / 평가 답변 | 국내 모델·판매 상태·필수 제약 |
| 근거 정합률 | 원문이 지지하는 주장 / 평가 주장 | 판정 규칙·문서 버전·조건 |
| 플랫폼 노출·인용 | 도구 정의의 건수·share | 접점·집계 단위·기간·시간대 |
| AI referral 세션 | 식별 규칙에 맞는 방문 세션 | referrer/UTM·봇·중복·리디렉션 |
| AI referral MAU | 해당 월 식별 AI 유입 사용자 수 | 식별 방식·월 기준·중복 제거 |
| 구매 CVR | 구매 세션 / 대상 세션 등 사전 정의 | 세션/사용자 분모·주문 상태·기간 |
| 유효 문의 CVR | 검증 문의 / 대상 세션 등 사전 정의 | 상담·데모·문의 자격·중복 |
| 귀속 CPA | 광고비 / 귀속 전환 | 귀속 모델·전환 창·비용 범위 |
| 증분 고객 가치 | 대조 조건 대비 추가 고객·마진 | 실험·불확실성·반품·서비스 비용 |

MAU는 월간 사용자, 세션은 방문 단위다. 사용자 식별이 부족하면 세션 수를 MAU로 이름 바꾸지 않는다. 자사 AI Chat 이용자와 외부 AI 유입자도 서로 다른 집단이며, 같은 고객이 두 집단에 있을 수 있다. 집단별 지표를 유지한 뒤 결합 분석에서 가능한 범위의 중복을 제거한다.

**가상 예시:** 한 고객이 같은 달 AI 링크로 세 번 방문하고 AI Chat을 두 번 사용해 한 번 구매했다면, 외부 AI 방문 3세션·식별 사용자 1명·AI Chat 이용 고객 1명·주문 1건이다. ‘외부 AI 고객 1명 + AI Chat 고객 1명 = 고객 2명’으로 합산하지 않는다. 실제 식별 가능 범위는 자사 수집·동의 조건에 따라 다르다.

## 4. AI 방문의 분류와 시계열을 유지하는 방법

| 상황 | 처리 원칙 — 운영 제안 | 기록할 것 |
|---|---|---|
| referrer와 UTM이 모두 AI | 동일 방문을 하나로 분류 | 원본 URL·수집 source/medium·세션 |
| paid 캠페인과 같은 source | 캠페인·매체·클릭 식별로 자연/유료 구분 | 광고 계정·campaign·이벤트 규칙 |
| 리디렉션·앱 전환 | 표식 유지·최종 수집값 대조 | 출발/도착 URL·전환 시각 |
| Direct로 복귀 | 연결 근거가 있을 때만 관계 분석 | 미식별 범위·고객 식별 한계 |
| 봇 방문 | 사람 방문 분석과 분리 | 식별 근거·필터 버전 |
| 채널 규칙 변경 | 과거 재집계 가능성·단절 표시 | 규칙·변경일·영향 범위 |

OpenAI의 UTM 안내는 검색 유입의 출처 표식이다. `utm_source` 하나만으로 구매 의도, 유료 여부, 월 사용자, 증분 구매를 확정할 수 없다. Direct 방문 전부를 AI로 돌리는 방식도 사용하지 않는다. 수집값과 분류 규칙을 보존해야 성장과 측정 방식의 변화를 구분할 수 있다. [UTM의 범위](evidence/OAI-REFERRAL-20261006-001.md)

## 5. 공개 benchmark: 어떤 성과를 비교했는가?

| 근거·관측 범위 | 확인된 수치 | 실제 비교·분모 | 적용 한계 |
|---|---|---|---|
| Adobe 미국 retail, 2026-03 | 구매 CVR 상대 +42% | 동월 non-AI 방문 구매율 대비 | 절대 CVR·한국 효과·인과 실험 아님 |
| Adobe 미국 retail, 2026-07 | 구매 CVR 상대 +60%, 장바구니 추가율 +28% | 구매와 cart 행동을 각각 비교 | 채널·고객·상품 구성 영향 |
| Adobe 미국 travel, 2026-07 | 구매 CVR 상대 −1% | non-AI와 거의 유사 | retail 우위의 전 업종 확장 불가 |
| Opollo IT 서비스 312개, 2025-01~2026-01 | AI 평균 14.2%·organic 2.8%, 중앙값 13.6%·2.5% | 상담 예약·데모·검증 문의, 월 AI 세션 10 미만·CVR 35% 초과 제외 | 일반 retail 구매율·전체 시장 평균 아님 |
| 독립 추천 audit, 09-16 제출 | UI/API 표시 도메인 겹침: ChatGPT 12.0%, Gemini 14.8% | 117개 질문·네덜란드 로그아웃 UI·반복 비교 | 구매 전환·한국 대표 표본 아님 |
| OpenAI 파트너 사례, 10-05 | WeightWatchers 귀속 CPA −15.3% | blended paid search benchmark 대비 | 표본·기간·원자료 부족, 증분 CAC 아님 |

[Adobe](evidence/ADI-MARKET-20261006-001.md) · [Opollo](evidence/OPO-BENCH-20261006-001.md) · [UI/API 연구](evidence/RES-AUDIT-20261006-001.md) · [광고 사례](evidence/OAI-ADS-20261006-001.md)

AI에서 이미 후보를 좁힌 고객이 사이트에 도착한다면 높은 전환율과 양립할 수 있다. 그러나 구매 의도가 높은 고객이 AI를 선택했을 가능성도 있어 관측 차이를 AI의 설득 효과로 확정할 수는 없다. Opollo의 14.2/2.8은 약 5.07배이지만 구매가 아닌 유효 문의이며, 제외 조건·평균 가중 방식·개별 세션 표본의 한계도 남는다.

### 숫자의 의미를 보여 주는 계산 예시

| 가상 데이터 | 방문 세션 | 구매 세션 | CVR |
|---|---:|---:|---:|
| non-AI | 10,000 | 200 | 2.0% |
| AI | 1,000 | 32 | 3.2% |

AI의 CVR 상대 차이는 +60%, 절대 차이는 +1.2%p다. 구매 세션은 32건이며, 더 높은 비율이 더 큰 거래 규모를 뜻하지 않는다. 이는 Adobe의 실제 절대 CVR가 아닌 계산 예시다.

**표본이 작을 때:** 50세션 중 구매 2건은 4%, 4건은 8%다. 구매 두 건의 차이가 상대 +100%를 만들지만, 이 숫자만으로 개선을 확정하기 어렵다. 세션·전환 수·반복 기간과 불확실성을 함께 보고하고, 실제 자료 없이 통계적 유의성을 약속하지 않는다.

## 6. 실제 소비자 화면과 API 관찰을 분리하기

| 관찰 경로 | 기록할 최소 조건 | 따로 볼 것 |
|---|---|---|
| 소비자 UI | 플랫폼·국가·언어·시점·로그인·대화 맥락 | 개인화·모델 미표시·상품 카드·광고 |
| API | 모델·검색 도구·설정·질문·응답 | UI와 다른 시스템·노출 층위 |
| 반복 관찰 | 회차·질문 순서·간격·독립 세션 여부 | 단일 결과의 변동·새 출처 |
| 사실 판정 | 제품 원문·모델·버전·지원 주장 | 인용 존재와 주장 지지 여부 |

독립 연구는 실제 질문에서 소비자 UI와 API가 표시하는 출처가 크게 달랐음을 보고했다. 연구의 1,755개 관찰 시도와 분석 답변 1,536개는 다른 분모이며, AIO도 모든 검색에서 나타난 것이 아니다. 표시 인용·검색 도구가 반환한 자료·grounding 정보는 같은 ‘출처 수’로 합산할 수 없다. [연구 방법·한계](evidence/RES-AUDIT-20261006-001.md)

API는 설정을 고정해 반복하기에 유용하지만 소비자가 보는 경험을 완전히 대신하지 않는다. 차이가 접근 방식 하나 때문에 생겼다고 단정할 수도 없다. 모델·검색·제품 구성이 다를 수 있다. API 평가와 실제 UI 표본을 나란히 관리하고 무엇을 대표하는지 명시해야 한다.

**실패를 다루는 기준**

1. 유효 답변·실질 추천·추출 성공의 정의를 사전에 고정한다.
2. 빈 응답·도구 오류·화면 추출 실패·추천 없음의 수를 분리한다.
3. 제품 추천률과 기술 실행 성공률의 분모를 구분한다.
4. 실패를 조용히 제외해 성공률을 높이지 않는다.

## 7. 귀속과 증분을 구분하는 사업 평가

| 질문 | 관측·계산 | 추가로 필요한 것 |
|---|---|---|
| 어느 접점에 주문을 연결했는가? | 정한 귀속 모델·창의 주문 | 중복·복귀·다른 접점 규칙 |
| 광고/정보 개선 없이도 구매했을까? | 대조 조건과 차이 | 실험 설계·동시 변화·불확실성 |
| 추가 고객이 가치 있는가? | 신규 고객·반복 구매·마진 | 기간·취소·반품·서비스 비용 |
| 추천이 실제 구매를 완결했는가? | 승인→주문→설치·지원 | 조건 유지·이행 실패·복구 |

귀속 모델은 관측한 주문을 접점에 배분하는 규칙이고, 증분은 그 활동이 없었을 때와 비교해 추가로 발생한 결과다. 광고가 없었어도 구매했을 고객이 섞일 수 있으므로 낮은 귀속 CPA만으로 증분 마진을 확정하지 않는다. 정보 개선 전후에도 플랫폼 변경·프로모션·재고·계절이 동시에 바뀌면 효과가 섞인다.

가능한 접근은 제품군·질문군의 정보 개선 전후와 비교군, 지원되는 광고의 지역 비교 실험 등이다. 외부 추천을 완전히 무작위 통제하기 어려운 경우 ‘관측된 개선’으로 보고하고 인과 효과와 구분한다. 광고 비용 계산은 [G-5](G-5_ai_ads_monetization.md), 이행 지표는 [G-4](G-4_agentic_commerce.md)에 연결한다.

## 8. 한국 브랜드의 검증·보고 구조 — 제안

| 순서 | 검증·집계 | 의사결정에 남길 결과 |
|---|---|---|
| 1. 범위 | 국가·제품군·설치/비교 질문·성공 조건 | 기준선·표본·기간 판단 |
| 2. 정의 | 자연 AI·paid AI·자사 AI Chat·검색·주문 규칙 | 지표 사전·중복·미식별 범위 |
| 3. 관측 | 실제 UI 품질, 플랫폼 자료, landing·이벤트 | 모델·근거·방문·조건 유지 |
| 4. 개선 | 콘텐츠·피드 변경과 판촉·재고·플랫폼 변화 기록 | 전후 조건·비교군·동시 변화 |
| 5. 결과 | 문의·주문·신규·취소·설치·마진 연결 | 귀속 효율·추가 효과·불확실성 |

**월간 보고의 세 묶음**

- **발견 품질:** 고객 제약 충족, 정확한 국내 모델, 근거 지지, 오류·변동.
- **관측 접점:** 도구별 노출·인용, 식별 방문·사용자, 자연/유료 구분과 누락.
- **사업 결과:** 주문·유효 문의·신규 고객·이행·취소·마진, 귀속과 증분의 구분.

세 묶음을 연결하면 ‘인용은 늘었는데 구매가 줄었다’는 상황에서 가격·재고·고객 의도·설치 조건 중 어디를 확인할지 정할 수 있다. 지표 하나의 상승으로 전체 성과를 설명하는 것보다 다음 실행을 선택하는 데 도움이 된다.

## 9. 자주 생기는 보고 오류의 판독

| 관측 | 가능한 설명 | 먼저 확인할 것 |
|---|---|---|
| 인용 증가·방문 정체 | 클릭 없는 답변·질문 구성 변화 | 노출 조건·의도·landing |
| AI CVR 상승·방문 감소 | 높은 의도 고객만 남음 | 전환 수·객단가·신규·마진 |
| Direct 증가·AI 정체 | 미식별 복귀 또는 다른 원인 | 실제 연결 근거·수집 변경 |
| 분류 변경 후 AI 급증 | 측정 규칙에 따른 재분류 | 과거 재집계·시계열 단절 |
| 플랫폼 내 주문·웹 방문 없음 | 웹 세션 없는 거래 | 주문·결제·동의·경로 |
| 귀속 CPA 개선·이익 정체 | 중복 귀속·할인·취소·운영 비용 | 추가 고객·순기여·기간 |

기존 [Promodo 사례](../AI_SalesMarketing/cases/PMD-20261001-001.md)의 전후 관측·증분 한계도 유지한다. Brand Answer Engine의 발견 품질과 AI Chat의 고객 조건 해결을 별도로 평가하고, 실제 주문·지원까지 이어지는 범위를 공동 판단하는 구조를 제안한다.

_검증 범위: 공개 도구·원문 benchmark·독립 연구를 종합했다. 계정 접속·내부 사용자/주문 집계·추적 코드 배포·한국어 UI 실험·대조 실험을 수행하지 않았다. 계산·지표·보고 구조는 설계 예시이며 내부 성과가 아니다._
