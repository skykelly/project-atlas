# G-3. AI 크롤러·콘텐츠 접근·llms.txt

[목차](README.md) · [이전: 탐색 경로](G-2_query_fanout.md) · [다음: 측정](G-4_measurement.md)

> **핵심 결론**
> AI 접근은 검색·학습·사용자 조회의 목적별 정책으로 관리하고, 파일·마크업의 효과는 해당 플랫폼의 공식 지원에 한정해 판단한다.

_공식 자료 확인일: 2026-10-06_

## 검증 근거에서 도출한 인사이트

### 1. 검색 허용과 학습 허용은 별도 선택이다

[OpenAI 크롤러 문서](evidence/OAI-CRAWL-20261006-001.md)는 목적별 독립 설정을 확인해 준다. ‘AI 봇 차단’ 한 줄보다 검색 발견, 모델 학습, 고객이 요청한 조회의 목적을 구분하는 접근 정책이 필요하다는 해석이다.

### 2. llms.txt의 효과를 플랫폼 간에 일반화하지 않는다

[Google의 2026년 명확화](evidence/GOO-LLMS-20261006-001.md)는 Google 검색에 파일 추가를 효과의 전제조건으로 두지 말아야 할 근거다. 다른 시스템에서 사용하는 파일의 가치까지 부정하지는 않는다. 지원 문서·실제 호출·결과를 각각 확인한다.

### 3. 접근 허용은 정확한 정보 전달을 보장하지 않는다

페이지가 읽혀도 가격·재고·설치 조건이 오래됐거나 중요한 정보가 이미지·인증 화면에만 있으면 고객의 판단에 쓰기 어렵다는 운영 가설이다. 접근 성공과 정보의 정확성·신선도를 서로 다른 체크 항목으로 둔다.

## 접근 정책 비교

| 대상 | 확인 근거 | 실무 점검 |
|---|---|---|
| 검색·학습·사용자 조회 | [OpenAI 목적 분리](evidence/OAI-CRAWL-20261006-001.md) | robots·CDN·인증 규칙과 목적 대응 |
| Google용 llms.txt | [공식 효력 설명](evidence/GOO-LLMS-20261006-001.md) | 효과를 전제한 과제 우선순위 검토 |
| AI 검색 기술 조건 | [Google 발견 가이드](evidence/GOO-GEO-20261006-001.md) | 색인·설정·중요 정보 접근 |

## 우선 실행안 — 적용 가설

공개 제품 URL의 접근·렌더링·최신 정보를 점검하고 목적별 차단 사유를 기록한다. 사내 민감정보·개인정보에 대한 인증 정책은 별도로 유지한다. 실제 규칙 변경은 담당자가 영향 범위를 확인한 뒤 수행한다.

## 근거 범위

이번 검증은 공식 문서다. LGE.com robots·CDN·로그 또는 실제 봇 동작을 조사한 결과로 표현하지 않는다.

## 범위

AI 서비스가 웹 콘텐츠를 수집·검색·사용자 요청으로 조회하는 방식과 기업의 접근 통제를 조사한다. 크롤러 식별, robots 정책, 렌더링·색인, 콘텐츠 사용 조건, 제품 피드·API와 llms.txt 관련 공식 지원을 포함한다.

## 핵심 연구 질문

- 학습용 수집, 검색용 색인, 사용자 요청 조회는 어떻게 구분되는가?
- 어떤 크롤러·User-Agent·검증 방식이 공식 문서에 명시되는가?
- robots·접근 제한이 학습·검색·추천에 각각 어떤 영향을 주는가?
- 동적 페이지·로그인·탭·이미지 안의 정보는 실제로 읽을 수 있는가?
- llms.txt는 제안, 공식 지원, 관찰된 효과 중 어느 단계의 근거가 있는가?

## 비교·종합 기준

| 확인 항목 | 기록할 내용 |
|---|---|
| 목적 | 학습, 색인, 실시간 조회 또는 미공개 |
| 식별과 통제 | 공식 식별자, 검증·허용·차단 방식 |
| 읽기 조건 | HTML·렌더링·인증·지역 제한 |
| 정보 전달 | 웹 문서, 제품 피드, API, 별도 파일 |
| 효력 | 공식 지원 여부와 확인 가능한 실제 동작 |

## LGE.com 적용 가설

콘텐츠 접근을 허용하기 전에 정확한 제품 정보, 가격·재고의 신선도, 권한·사용 조건을 점검한다. 학습과 검색 목적이 구분된다면 목적별 정책을 검토할 수 있다는 가설을 두되 플랫폼 문서로 확인해야 한다.

llms.txt 추가만으로 GEO 성과가 좋아진다고 가정하지 않는다. 공식 지원 여부, 접근 로그와 검색·인용 변화가 함께 확인되는지 먼저 검증한다.

## 측정과 한계

크롤러 접근 성공·오류, 접근 가능한 주요 페이지 비율, 정보 갱신 지연과 답변의 오래된 정보 비율을 본다. 봇 접근은 실제 사용자 유입이나 추천 성과와 구분한다. User-Agent 문자열만으로 접근 주체의 신뢰성을 확정하지 않는다.

## 다음 조사

공식 크롤러·웹사이트 운영 문서의 갱신일을 확인한다. 정책 변경일과 시행일이 다르면 둘 다 남긴다. 국가·플랫폼별 예외를 검토한 뒤 제한된 테스트를 설계한다.
