# L-4. Enterprise AX / Agentic Operating Model

[LG Group 목차](../README.md) · [조사 이력](../LOG.md)

**조사 기간: 2026-01-01~2026-10-06.** 공식 회사·고객·플랫폼 원문을 확인했다. 수치의 출처·발표일·측정 조건은 연결한 사례 문서에 기록했다. 아래 사업적 의미와 비교 종합은 조사자의 해석이며, 회사 발표와 독립 성과 검증은 구분한다.

## 1. 개인 도구를 업무 시스템으로 밀어 넣는다

2026년 LG의 기업 AX는 **전자 전사 플랫폼, 화학 현업 Agent 교육, CNS의 고객 업무 자동화·데이터 운영·개발 플랫폼·외부 모델 공급**으로 갈라진다. 각 체계는 읽는 데이터, 실행하는 행동, 과금 근거가 다르다.

종근당 APQR 서비스는 고객명, 구축 완료, 문서 생성 시간 변화를 한 사례 안에서 연결한다. 교육·계약·제품 출시보다 강한 성과 근거다. LG CNS는 모델 접근권을 넘어 완결된 업무 공정을 판매한다.

| 경로 | 2026년 확인 결과 | 변화의 핵심 |
|---|---|---|
| 전사 플랫폼 | 전자 LGenie의 Agent 플랫폼 진화와 2~3년 내 생산성 30% 향상 목표 | 개인 답변에서 부서 업무 연결로 확장 |
| 현업 확산 | 화학 최근 6개월 3,000명 초과 교육 | 업무 담당자가 문제·Agent를 직접 설계 |
| 고객 업무 구현 | 종근당 APQR 구축 완료·문서 생성 시간 90% 이상 단축 발표 | 여러 업무 시스템에서 자료를 모아 검증·작성 |
| 데이터 운영 | 계열사 품질 PoC 이후 Foundry·AIP 본사업 계약 | 분산 데이터와 의사결정 연결 |
| 시스템 개발 | AIND 출시·금융 COBOL→Java 적용 중 | 기업 지식·명세를 분석·코딩·테스트에 반영 |
| 공급 사업 | OpenAI·Anthropic 계약과 고객 확보 | 모델 접근에 컨설팅·구축·운영 결합 |

각 행의 근거는 아래 해당 절과 사례에 연결한다. 그룹 공통 생산성 실적이나 단일 운영 조직을 발표한 표가 아니다.

## 2. AI·클라우드 매출에서 Agent 매출을 분리해 본다

CNS의 2026년 상반기 공식 잠정 실적은 전체 매출 2조 8,358억원·영업이익 2,221억원, AI·클라우드 매출 1조 6,714억원으로 구성된다. AI·클라우드는 전체의 약 59%, 전년 대비 5.1% 성장했다. 이 범주에는 클라우드·데이터센터가 포함되므로 **1조 6,714억원을 Agentic AI 매출로 볼 수 없다.**

| 실적 범위 | 수치 | 이 보고서에서의 용도 |
|---|---|---|
| CNS 전체 상반기 | 매출 2조 8,358억원·영업이익 2,221억원 | AX 공급 사업의 기업 규모 |
| AI·클라우드 | 매출 1조 6,714억원·약 59% 비중 | 성장 사업의 구성; Agent 단독 실적 아님 |
| 상반기 전체 성장 | 매출 +6.1%·영업이익 +1.1% | 매출 확대와 이익 성장의 차이 |
| 2분기 전체 | 영업이익 1,279억원·전년 대비 -9.2% | 상반기 성장만으로 분기 수익성을 단정하지 않음 |

**해석:** 공개 실적은 AI를 실제 고객 사업으로 공급하는 기반을 보여준다. 그러나 고객 계약 증가가 곧 높은 수익성의 반복 SW 매출로 이어지지는 않는다. 구축 인력·통합·지원이 필요한 사업에서는 매출 성장과 이익을 함께 봐야 한다. 개별 Agent 상품 매출·갱신률·마진은 공개되지 않았다. [실적 범위와 원문](../cases/LG-CNS-AX-RESULTS-20261006-001.md)

## 3. 전자 LGenie: 업무 도구에서 전사 플랫폼으로

1월 8일 공개한 경영 방향은 AX를 개발·판매·SCM·조달·마케팅에 적용하고 LGenie를 전사 AI Agent 플랫폼으로 발전시키는 것이다. EXAONE과 Azure AI Services·ChatGPT·Gemini를 함께 설명한다. 자체 모델과 외부 모델을 업무 목적에 맞게 연결하는 방향이며 자체 모델만 쓰는 전략으로 읽지 않는다.

전사 플랫폼은 부서마다 다른 업무 맥락과 데이터 접근을 한 사용 환경에 연결한다. 반복 작업의 결과를 다음 작업으로 넘기면 답변 도구가 실행 체계로 바뀐다. 다만 이 부분은 발표를 바탕으로 한 사업 해석이다. 모든 부서의 자동 실행 범위나 공통 권한 체계를 공개한 것은 아니다.

| 발표 요소 | 직접 확인한 내용 | 성과로 읽는 범위 |
|---|---|---|
| 활용 범위 | 개발·영업·SCM·조달·마케팅 AI 적용 | 활용 방향·영역 |
| 플랫폼 변화 | LGenie를 전사 Agent 플랫폼으로 진화 | 플랫폼 전략 |
| 생산성 | 2~3년 내 전체 30% 향상 | 목표; 현재 달성률 아님 |

**해석:** 같은 생산성 목표라도 개발 결함, 조달 리드타임, 영업 처리 시간은 분모가 다르다. 전사 목표는 방향을 정한다. 개별 과제는 품질·비용·납기 안에서 결과를 측정해야 한다. 원문은 공통 산정식을 공개하지 않았다. [LGenie 사례](../cases/LG-LGENIE-AX-20261006-001.md)

## 4. 화학: 현업이 자기 업무를 설계하는 확산 방식

화학은 5월 28일 최근 6개월 교육 3,000명 초과·사무직 약 절반 수료를 공개했다. 리더 약 1,000명을 먼저 교육하고 현업이 자기 업무에 맞는 Agent를 만드는 방식이다. 문서·분석·구매·일정·규정 안내·특허 정보 등이 활용 영역으로 제시됐다.

회의 PPT 취합 사례는 문제를 작게 나누는 방식이 잘 드러난다. 서로 다른 양식의 파일을 열어 글꼴·순서를 맞추고 합치는 작업에서 자료 정리를 자동화해 1시간을 10분으로 줄였다고 설명한다. 이 수치는 특정 반복 업무를 측정했다. 전사 직원 전체의 생산성 수치로 확대할 근거는 없다.

| 확산 요소 | 공개된 방식 | 운영 모델에 대한 해석 |
|---|---|---|
| 리더 경험 | 리더 우선 실습 | 과제 선정·업무 변경의 의사결정 기반 |
| 개인 문제 | 1인 1에이전트 | 담당자가 입력·출력·업무 제약을 정의 |
| 팀 흐름 | 하반기 Workflow 워크숍 계획 | 개인 자동화를 팀 공정으로 연결할 방향 |

현업 설계의 장점은 실제로 시간이 쓰이는 세부 문제를 발견한다는 데 있다. 반면 개인별 도구가 팀 데이터와 연결되는 순간 공통 양식·권한·버전 관리가 중요해진다. 교육 수료자와 반복 활성 사용자, 개인 Agent 수와 실제 운영 중인 Agent 수는 공개 자료에서 같은 숫자로 잡히지 않는다. [교육·업무 예시 근거](../cases/LG-CHEM-AGENTS-20261006-001.md)

## 5. 종근당 APQR: 실제 시스템에 연결된 멀티 Agent 사례

### 5.1 어떤 업무인가

APQR(Annual Product Quality Review)은 연간 제품 품질평가 보고서다. 자료가 품질경영시스템(QMS)과 실험실정보관리시스템(LIMS)에 흩어져 있으면 작성자가 데이터를 모으고 일치 여부를 확인한 뒤 보고서를 작성해야 한다. CNS는 1월 21일 종근당의 해당 서비스 구축 완료를 발표했다.

### 5.2 공개된 실제 흐름

| 단계 | 공개된 처리 | 사람이 집중하는 일 |
|---|---|---|
| 수집 | QMS·LIMS 등에서 자료 연결 | 대상·자료 범위 확인 |
| 분석·검증 | 약 30개 Agent의 협업 구조 | 결과의 타당성 판단 |
| 보고서 작성 | AgenticWorks 기반 문서 생성 | 최종 검증 |

회사는 **문서 생성 시간 90% 이상 단축**을 발표했다. 기준 절대 시간·대상 보고서 수·반복 측정 기간은 미공개이며 최종 검증까지 포함한 전체 승인 리드타임으로 확대하지 않는다. 위 표의 사람 역할 설명은 공개된 최종 검증 방향과 업무 구조를 묶은 해석으로, 세부 승인 화면이나 자동 승인 기능을 확인한 것은 아니다.

**사업적 의미:** 고객은 특정 보고서 업무의 완결성을 구매했다. 데이터 연결·산업 양식·분석·검증·작성을 제품화하면 외부 모델이 바뀌어도 업무 자산은 남는다. 자동화 이후 사람은 최종 검증과 예외 판단을 맡는다. [구축·성과·조건](../cases/LG-CKD-APQR-20261006-001.md)

## 6. Foundry·AIP: 데이터가 연결돼야 운영 판단으로 넘어간다

3월 12일 발표는 팔란티어와의 전략적 계약, 전담 FDE 조직, LG 계열사 한 곳의 품질 PoC 후 본사업 계약을 확인한다. Foundry는 분산 데이터의 통합·정제와 운영 기반, AIP는 그 위의 생성형 AI 판단 지원으로 설명된다. 해당 계열사명과 품질 개선율은 공개되지 않았다.

| 기능 구분 | 공개된 역할 | 다른 AI 도입과의 차이 |
|---|---|---|
| Foundry | 데이터 통합·정제·운영 체계 | 문서 검색보다 시스템 상태 연결이 중심 |
| AIP | 통합 데이터 기반 판단 지원 | 모델이 같은 업무 상태를 참고하게 함 |
| FDE | 산업 과제 발굴·현장 실행 | 플랫폼 도입을 실제 과제로 바꾸는 인력 |

**해석:** 품질 이슈 하나를 판단할 때 제품·공정·설비·검사 이력이 연결돼야 같은 문제를 이야기할 수 있다. 이 관계를 구현하려면 모델 질의보다 훨씬 많은 데이터 정리와 현장 합의를 거쳐야 한다. FDE는 그 간극을 줄이는 실행 조직으로 읽힌다. 이 설명은 품질 업무의 일반 구조를 이용한 해석이며 해당 고객의 상세 데이터 모델을 확인한 것은 아니다. 본사업 계약은 상업적 진전이지만 전면 가동·ROI의 증거와 구분한다. [계약·고객 단계](../cases/LG-PALANTIR-20261006-001.md)

## 7. AIND: 기업 시스템을 이해하는 개발 Agent

6월 8일 출시한 DevOn Agentic AIND는 자연어 요구→분석·설계→코딩→테스트·품질 검증을 전문 Agent로 분해한다. 기존 소스·산출물·개발 표준·보안 규정을 구조화한 **Knowledge Foundation**과 사전 명세에 따라 작업하는 Spec-Driven Development가 중심을 잡는다. Cline과 공동 개발했다.

| 단계 | 공개된 구현 방향 | 기업 고객에게 중요한 이유 |
|---|---|---|
| 요구 분석·설계 | 요구 문서에서 구조 설계 | 기존 계좌·업무와 연결할 조건 파악 |
| 코드 생성 | 기업 개발 표준을 반영 | 그럴듯한 코드보다 운영 체계와의 호환 |
| 테스트·검증 | 명세 기준으로 결과 점검 | 기능 변경이 다른 업무에 미치는 영향 확인 |
| 사용자 검토·승인 | 결과 검토 역할 | 자동 생성과 변경 책임의 연결 |

발표는 예·적금 자동이체 서비스 예시와 국내 대형 금융사의 COBOL→Java 적용 중 상태를 제시한다. 예시는 기능 설명이고 고객 프로젝트 완료 증거가 아니다. 수 주가 소요되던 작업을 분 단위로 줄일 수 있다는 설명도 특정 코드 분석·변환·검증 범위이며 전체 개발 일정 단축률로 쓰지 않는다.

**해석:** 이 사업은 고객 시스템의 맥락을 재사용해 차별화한다. 지식 기반과 명세가 연결되면 변경 요청이 기존 업무 규칙과 충돌하는지 판단할 근거가 생긴다. 자동화의 수익 가치는 코드 작성 시간뿐 아니라 검토·재작업·운영 장애까지 줄일 수 있을 때 확대된다. 현재 고객별 결함·전체 비용의 비교값은 미공개다. [AIND 원문·적용 범위](../cases/LG-AIND-20261006-001.md)

## 8. 외부 모델 공급: 접근권과 업무 구현을 묶는 사업

| 협력 | 확인된 2026년 결과 | 고객에게 제공하는 범위 |
|---|---|---|
| OpenAI | 2월 리셀러·서비스 구현 계약; 4월 약 10개 기업 고객 발표 | 도입 컨설팅·기술 지원·구축·활용 워크숍 |
| ChatGPT Edu | 4월 교육 채널 계약 | 대학 도입 지원; 대학별 실적은 미공개 |
| Anthropic | 6월 Claude Enterprise 계약·CNS 전 임직원 사용 제공 | 그룹·외부 기업 단계적 확장 계획 |

CNS의 OpenAI Launch Center에는 AI 엔지니어·아키텍트·컨설턴트가 참여한다. 단순한 좌석 판매에 그치지 않고 업무 통합과 활용 지원을 결합하는 구조다. Claude 계약은 그룹 전 계열사에 적용 가능한 형태지만 전 계열사 배포 완료를 뜻하지 않는다. CNS 내부에서는 Claude·ChatEXAONE 등 멀티 AI 체계를 설명했다.

**해석:** 외부 모델을 쓰더라도 고객 업무 데이터와 시스템을 연결하는 SI·운영 역량은 수익 접점을 만든다. 다만 리셀러 계약이나 내부 사용 제공만으로 고객 효과가 보장되는 것은 아니며, 모델별 비용·업무 품질·운영 지원이 각 프로젝트의 경제성을 결정한다. [OpenAI 채널](../cases/LG-OPENAI-CHANNEL-20261006-001.md), [Claude 도입](../cases/LG-CLAUDE-20261006-001.md)

## 9. 비교 종합: Agentic Operating Model은 업무별로 구현된다

| 구현 경로 | 출발점 | 확인된 결과 | 반복 가능한 가치에 대한 해석 |
|---|---|---|---|
| 개인 업무 | 문서·반복 작업 | 교육·단일 취합 사례 | 현업 문제 발견과 작은 자동화 |
| 산업 보고서 | 업무 시스템·품질 규칙 | 종근당 구축·문서 시간 변화 | 산업 공정과 검증을 묶은 서비스 |
| 데이터 운영 | 여러 시스템의 상태 | 품질 PoC→본사업 계약 | 판단에 필요한 공통 데이터·관계 |
| 개발 Agent | 레거시·표준·명세 | 출시·금융 적용 중 | 고객 IT 지식의 개발 공정 재사용 |
| 모델 공급 | 기업 도입 수요 | 계약·고객 확보 | 선택·교육·구축·운영 지원 |

**종합 판단:** LG의 AX는 입력과 결과가 명확한 업무를 시스템에 연결할 때 성과를 낸다. 종근당은 보고서 공정, AIND는 개발 공정, Foundry·AIP는 운영 데이터 공정을 다룬다. LGenie와 현업 교육이 확산 통로를 제공한다. 공개 근거는 각 체계를 하나의 그룹 공통 플랫폼으로 묶지 않는다. 다만 모델 접근→업무 지식→실행 공정→검증이라는 운영 순서는 반복된다. 다음 단계는 도입·교육·계약을 넘어 활성 사용, 품질, 재작업, 총비용, 갱신률을 같은 계정에서 추적하는 일이다. 전사 순 ROI는 아직 공개되지 않았다.
