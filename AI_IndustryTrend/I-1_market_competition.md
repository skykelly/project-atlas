# I-1. AI 시장·주요 기업 경쟁

[주제 목차](README.md) · [모델 역량·비용](I-2_models_cost.md) · [변경 이력](LOG.md)

조사 기간: **2026-01-01~2026-10-07**. 기간 중 공개된 자료와 확인일 현재 문서를 사용한다. 2026년 발행 보고서가 2025년을 관측하면 그 시차를 표시한다. 금액의 B는 billion(10억), M은 million(100만)이다.

2026년 하반기에는 고객이 고급 모델을 선택적으로 구매하고, 기존 SaaS가 AI 실행을 별도 과금하며, 클라우드가 장기 계약을 설비로 바꾸는 흐름이 겹친다. 공급자의 규모만으로 이 변화를 설명할 수 없다. 아래에서는 실적·구매 데이터·공개 모델 생태계를 연결해 **어디서 수익을 확보하고, 누가 비용과 운영 부담을 떠안는지** 분석한다.

## 1. 같은 AI 수요가 여러 회사의 매출로 잡힌다

기업이 업무 Agent를 한 번 실행해도 소프트웨어 구독료, 모델 추론료, 클라우드 연산료가 동시에 발생한다. 클라우드는 다시 서버와 칩을 산다. 하나의 최종 수요가 여러 공급자의 매출에 중복 포착된다. 단순 합산하면 시장 규모가 부풀어 오른다.

| 층위 | 고객이 구매하는 것 | 관측할 지표 | 기업의 선택 문제 |
|---|---|---|---|
| 연산·하드웨어 | 칩·서버·네트워크·설비 | 공급 매출·용량·실제 가동 | 연산 확보와 공급 의존 |
| 클라우드·모델 유통 | 연산·관리형 API·보안·계약 | 서비스 소비·리전·공급 모델 | 기존 계정·권한·계약을 재사용할지 |
| 모델 | 추론·생성·도구 선택 능력 | 품질·지연·성공 과업당 비용 | 어떤 과업을 어느 모델에 맡길지 |
| 업무 접점·실행 | 사용자가 일하는 화면과 실행 환경 | 좌석·활성 사용·완료율 | 실제 업무에 연결되는지 |
| 기업 지식·운영 | 권한·최신 정보·평가·복구 | 정보 정확성·실행 오류·운영 비용 | 조직이 지속해서 통제할 수 있는지 |

각 층위는 다른 상품을 판다. 공급자를 비교할 때도 그 상품의 매출·용량·실행 결과를 따로 읽어야 한다. 고객 기업의 구매 판단에는 업무 완료율·복구·총비용이 함께 들어간다.

## 3. 투자·매출·도입을 섞으면 시장 규모가 왜곡된다

### 3.1 투자와 도입의 기초 규모

Stanford AI Index 2026은 **2025년 기업 AI 투자 $581.69B**, 그중 민간 투자 $344.66B를 제시한다. 같은 보고서의 조직 도입 지표는 설문 응답에 기반한다. 투자 확대는 자금이 배치됐다는 뜻이지, 그만큼의 AI 상품이 판매됐다는 뜻은 아니다. [조건·근거](evidence/HAI-ECON-20261006-001.md)

- **투자:** 미래 연산·제품·기업 인수에 배치된 자금.
- **매출:** 정해진 기간에 인식한 판매 실적.
- **Run rate:** 최근 수익화 속도를 연간으로 환산한 규모. 그 속도가 연말까지 유지되는지는 별도다.
- **도입:** 사용 여부·범위. 좌석 구입과 실제 사용·결과는 구분한다.

### 3.3 고객 수·모델 지출·토큰 점유율은 서로 다른 승자를 만든다

Ramp가 2026-08-12 공개한 7월 관측에서 Anthropic에 비용을 지불한 기업 비율은 43.5%, OpenAI는 39.7%였다. 같은 자료의 모델별 집계에서는 Fable 5가 Anthropic 토큰의 6%, 모델 지출의 11.4%를 차지했다. GPT-5.6 Sol은 OpenAI 토큰의 25%, 지출의 23%였다. Fable의 모델 귀속 지출은 Sol의 약 75%였다. [원문·표본](evidence/RAMP-DEMAND-20261007-001.md)

| 관측 | 분석 | 아직 확인할 수 없는 것 |
|---|---|---|
| Anthropic의 유료 구매 기업 비율이 더 높음 | 공급자를 한 번이라도 구매하는 폭에서 우세 | 계약 총액·모든 고객의 매출 점유율 |
| Fable의 토큰 비중보다 지출 비중이 큼 | 비싼 모델이 적은 사용량으로 더 큰 비용을 차지 | 그 추가 비용에 상응하는 업무 가치 |
| Sol의 모델 귀속 지출이 Fable보다 큼 | 공급자 도입률과 개별 프리미엄 모델의 판매력이 다르게 움직임 | 모델 품질이 구매를 유발한 인과 효과 |
| 모델 serving 플랫폼 사용이 AI 사용 기업의 6.1% | 다중 모델을 선택하는 별도 구매 경로가 형성됨 | 전체 기업의 중국 모델 사용률·기업 내부 자체 배포 |

Ramp는 고객의 결제 기록을 관측한다. 모델별 토큰 집계는 별도 비용 관리 제품을 연결한 기업으로 구성되며 기술 기업 쪽으로 기울어 있다. 비율을 미국 기업 전체의 확정 점유율로 확대하지 않는다. 이 경계 안에서도 읽을 수 있는 변화는 명확하다. **기존 고객에게 더 비싼 모델을 파는 전략이 자동으로 작동하지 않는다.** 고객은 이미 쓰는 모델이 업무를 충분히 처리하면 새 플래그십의 추가 비용을 거절할 수 있다.

9월 Anthropic의 효율 개선은 이 수요 관측과 맞물린다. 다만 회사가 Ramp 결과 때문에 제품을 바꿨다는 근거는 없다. 고급 모델의 가격을 낮추고 일상 업무용 모델의 토큰 소비를 줄이는 방향은 고객의 지불 조건을 넓히는 전략으로 해석할 수 있다. [가격·효율 변화](I-2_models_cost.md)

### 3.4 Oracle: 계약이 쌓여도 현금은 설비에 먼저 들어간다

Oracle의 2026-09-10 FY27 Q1 발표는 연산 수요의 크기와 자금 부담을 함께 드러낸다. Cloud Infrastructure 매출은 $7.4B, 전년 동기 대비 121% 증가했다. RPO는 $664B이며 신규 AI 클라우드 계약은 $30B 초과였다. 같은 분기 영업현금흐름은 $23B, 잉여현금흐름은 -$5B였다. [공식 실적·조건](evidence/ORCL-EARN-20261007-001.md)

| 항목 | 사업에서 발생한 일 | 해석 |
|---|---|---|
| 실제 IaaS 매출 | 제공한 클라우드 서비스의 판매를 인식 | 계약 수요의 일부가 매출로 전환 |
| RPO | 아직 수행하지 않은 계약 의무를 누적 | 미래 수행 규모를 표시; 당기 매출·현금과 구분 |
| 영업현금흐름과 잉여현금흐름의 차이 | 영업 유입 이후 설비 투자 등이 현금을 사용 | 수요 증가와 자금 압박이 같은 분기에 공존 |
| 분기 추가 데이터센터 용량 850MW | 회사가 공급 확대를 보고 | 공급 진전의 근거; 개별 고객 가동률·ROI는 미공개 |

이 사례는 ‘AI 수요가 크다’와 ‘설비 투자금을 빠르게 회수한다’를 분리한다. 계약 기간, 선급금, 장비 조달 방식, 전력 확보와 가동 일정이 회수 속도를 결정한다. 장기 약정을 확보한 공급자는 증설을 앞당길 수 있지만, 고객 집중과 납기 지연을 함께 떠안는다. RPO를 성장률에 바로 대입하면 그 시간차가 사라진다.

기업 구매자에게도 이 차이는 직접적인 문제다. 약정 용량이 실제 리전·모델·응답시간으로 제공돼야 서비스를 운영할 수 있다. 장기 최소 사용 계약은 단가를 낮출 수 있지만, 추론 효율 개선이나 수요 감소가 발생하면 사용하지 않은 용량에도 비용을 지불하게 된다. 이 문단은 계약 구조의 분석이며 특정 고객의 미사용 비용을 확인한 결과는 아니다.

## 4. 기업 전략 비교 — 모델·연산·유통·업무 접점이 겹친다

| 기업 | 확인한 경쟁 기반 | 기업 고객에게 주는 선택지 | 선택할 때 확인할 사항 |
|---|---|---|---|
| Microsoft | Azure와 M365 유료 업무 접점 | 기존 업무 화면과 클라우드 소비를 활용 | 좌석·활성 사용·업무 완료를 별도로 측정 |

한 기업이 경쟁자·투자자·연산 공급자·유통 파트너 역할을 동시에 맡는다. [open-weight 비교](evidence/OPEN-MODELS-20261006-001.md)까지 포함하면 승패는 모델 점수 하나로 갈리지 않는다. **기업의 업무·데이터·예산에 들어가는 경로**가 실제 지배력을 만든다.

### 4.1 공개 모델은 수정·배포 경로에서 영향력을 축적한다

Hugging Face의 2026-08-14 보고서에서 Qwen 파생 모델은 151,448개였다. 공개 모델의 상위 1.5% 저장소가 다운로드의 99.2%를 차지했고, 85.6%는 누적 다운로드가 200건 미만이었다. [Hub 원문·관측 범위](evidence/HF-ECOSYSTEM-20261007-001.md)

파생 모델 수는 매출을 측정하지 않는다. 대신 개발자가 어느 기반 모델에 튜닝·양자화·배포 도구를 붙였는지 드러낸다. 기업이 이미 Qwen 기반 포맷과 serving 환경을 구축했다면 다음 프로젝트도 같은 계열을 검토할 유인이 생긴다. 모델을 무료로 배포한 공급자는 API·클라우드 소비와 개발자 생태계에서 수익 기회를 얻을 수 있다. 실제 수익 전환율은 이 자료로 계산할 수 없다.

**기업은 배포 도구까지 호환해야 모델을 낮은 비용으로 교체할 수 있다.** 가중치를 내려받아도 상업 라이선스, 양자화 품질, GPU 메모리와 운영 인력이 맞지 않으면 교체 비용은 남는다. API 공급자 의존을 줄이는 선택이 특정 serving 프레임워크나 커뮤니티 변환본에 대한 의존을 늘릴 수도 있다. [배포 조건](I-2_models_cost.md)

## 5. 공급자 매출과 고객 ROI는 반대 방향으로 움직일 수 있다

유료 좌석 증가와 클라우드 소비 증가는 공급자에게 매출이다. 고객에게는 비용일 수 있다. 이를 성과로 바꾸려면 구입한 기능이 실제 업무에 쓰이고, 사람이 결과를 수정하는 시간이 줄며, 처리량·품질·고객 가치 중 하나가 개선돼야 한다.

| 시장 관측 | 기업 내부에서 대응해 볼 지표 | 잘못된 해석 |
|---|---|---|
| 유료 좌석 확대 | 월 활성 사용자·반복 업무 사용·좌석당 유효 결과 | 구입한 좌석 전부가 생산성 향상 |
| API 소비 확대 | 성공 과업 수·성공당 총비용·재시도 | 토큰이 늘면 업무 가치도 증가 |
| 모델 가격 인하 | 같은 과업·품질·지연 조건의 비용 | 단가 인하만큼 총비용 감소 |
| Agent 기능 증가 | 승인 포함 완료율·예외 처리·복구 시간 | 제품 발표가 완전자율 운영의 증거 |
| 인프라 투자 확대 | 공급 가능성·가동률·납기·실제 비용 | 투자 규모가 수익성·공급 안정성 보장 |

주간 보고서를 5분 만에 생성해도 담당자가 근거 오류와 표를 고치는 데 40분을 쓰면 생산성은 악화될 수 있다. 도구 비용과 검수를 포함한 ‘수락 가능한 결과’를 측정 단위로 삼아야 한다. 이 수치는 LG 성과가 아닌 측정 설계 예시다.

### 5.1 기존 업무 소프트웨어는 AI 사용을 새 과금 항목으로 바꾼다

Ramp의 2026-08-18 관측에서 전통 SaaS 공급자 중 AI 기능을 청구한 비율은 전년 8%에서 14%로 늘었다. 사용량 과금 제품은 embedded AI 지출의 36%를 차지했다. 전년에는 24%였다. 사용량 과금을 적용받는 기업의 연간 지출 중앙값은 좌석만 구매하는 기업의 10.6배였다. [원문·과금 분류](evidence/RAMP-SAAS-20261007-001.md)

이 차이를 요금제의 인과 효과로 읽으면 오류가 생긴다. 사용량 과금을 선택한 기업은 업무 규모와 실행 빈도가 더 클 수 있다. 그래도 공급자의 수익화 경로는 보인다. 기존 업무 화면에 AI를 넣고, 시험 제공을 유료 기능으로 전환하고, 실행량이 커진 고객에게 소비 기반 요금을 청구한다.

모델 API 가격이 내려가도 고객 청구액이 같은 폭으로 줄지는 않는다. SaaS 공급자는 권한·데이터 연결·승인·감사·업무 결과를 묶어 판매한다. 이 묶음이 고객의 구축비를 줄이면 토큰 원가와 다른 가격을 받을 수 있다. 반대로 고객이 기능을 거의 쓰지 않거나 결과를 자주 수정하면 추가 구독료의 근거가 약해진다. 기존 소프트웨어의 지배력은 업무 데이터와 실행 권한을 보유하는 한 유지될 수 있다. 범용 Agent가 같은 업무를 더 낮은 총비용으로 처리하고 데이터 이동까지 지원하면 그 가격 방어력은 줄어든다.

| 경쟁 변화 | 수혜를 볼 수 있는 위치 | 성립 조건·반대 신호 |
|---|---|---|
| 프리미엄 모델 구매가 제한됨 | 효율 모델·라우터·다중 모델 유통 | 업무 품질을 유지해야 함; 검수비가 늘면 절감 상쇄 |
| SaaS가 AI를 별도 청구 | 기존 데이터·업무 실행 접점 | 반복 사용과 구축비 절감; 낮은 활성률은 반대 신호 |
| 연산 계약이 공급보다 앞서 증가 | 용량을 실제로 제공하는 클라우드·장비 공급자 | 납기·전력·가동·현금 회수; 계약 규모만으로 판단 불가 |
| 공개 모델 파생 생태계 확대 | 튜닝·serving·클라우드·개발 도구 | 상업 권리와 운영 품질; 다운로드가 매출로 전환돼야 함 |

이 표는 전망을 검증할 조건을 제시한다. 네 흐름이 모든 기업에서 동시에 발생한다고 가정하지 않는다. 특히 모델 회사가 업무 접점을 직접 확보할수록 SaaS와의 협력·경쟁이 겹친다. 고객은 모델비, 업무 플랫폼비, 도구 실행비를 같은 과업 단위로 묶어 비교해야 이 경쟁의 이익을 가져갈 수 있다.

## 6. 한국 기업의 실행 판단 — 계약 경로와 공통 지식을 함께 설계

1. **기존 계약·권한을 확인한다.** 직접 모델 API, 기존 클라우드 marketplace, 업무 소프트웨어 구독 중 어떤 경로가 계정·보안·구매에 맞는지 비교한다. 같은 모델명도 버전과 도구·지역·요금이 같다고 전제하지 않는다.
2. **공통 지식과 평가를 확보한다.** 모델을 바꿀 때마다 제품·정책·고객 정보를 다시 만들지 않도록 지식 갱신과 접근 권한을 기업이 관리한다.
3. **완료 단위로 예산을 연결한다.** 좌석과 토큰을 기록하되 업무 수락률·실패 복구·사람의 검수비까지 함께 비교한다.
4. **시장 발표와 실제 제공을 나눈다.** 해외 제한 접근·리전 출시·한시 할인은 국내 구매·운영 가능성과 별도로 확인한다.

Knowledge Atlas는 모델 공급자를 바꿔도 유지할 공통 지식·권한·근거의 역할로, AgentOne은 어떤 업무를 누가 승인하고 어느 시스템에서 실행할지 관리하는 접점으로 검토할 수 있다. 이는 적용 가설이며 현재 구축 구조·계약·성과를 조사했다는 의미가 아니다.

## 7. 실행 판단

- **단일 시장 총액을 믿지 않는다.** 투자·연산 공급·클라우드·모델·업무 접점은 분모가 다르다.
- **유통과 실행 접점이 모델 경쟁의 승패를 바꾼다.** 직접 API, 다중 클라우드, 업무 화면이 데이터와 예산을 붙잡는다.
- **능력과 비용은 업무별로 다시 잰다.** 공급자 benchmark를 한국어·내부 도구의 성과로 치환하지 않는다.
- **공통 지식과 평가 체계가 공급자 교체권을 만든다.** 비교할 업무와 수락 기준을 먼저 고정한다.

모델별 구체적 비용·제공 조건은 [I-2](I-2_models_cost.md), 후속 조사 범위·한계는 [LOG](LOG.md)에 관리한다. 본문은 공식 자료에 기반한 경쟁 구도의 종합이며 모든 사업자·산업의 전수조사나 독립 손익 검증은 아니다.
